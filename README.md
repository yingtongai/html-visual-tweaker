# HTML Visual Tweaker

一个用于本地 HTML 页面的 Chrome 可视化编辑扩展。无需修改代码，直接在页面中选中文字、图片或其他元素，即可调整内容、样式、大小和位置，并将结果导出为可独立使用的新页面，或在确认后覆盖原 HTML。

当前版本：`0.10.6`

> 扩展只在 `file://` 本地 HTML 页面中启用，不会修改普通网站。安装和日常使用不需要 Node.js，也不需要运行 `receiver.js`。

## 主要功能

### 1. 直接选择和修改元素

- 点击页面中的文字、图片、按钮、卡片、列表等元素进行编辑。
- 支持选择标题内部的强调文字等行内元素。
- 修改文案、字体、字号、颜色、宽高、外边距、圆角和位移。
- 拖动选中框的四个角调整元素大小。
- 工具栏和属性面板可以整体拖动，首次选择元素时会尽量避开目标区域。

### 2. 移动和精确调整

- 按住鼠标直接拖动元素。
- 移动时显示对齐参考线，并吸附附近元素的边缘或中心。
- 使用方向键每次移动 `1px`。
- 使用 `Shift + 方向键` 每次移动 `10px`。
- 使用 `Alt + 方向键` 调整元素宽度或高度。

### 3. 图片与文字

- 选中图片后点击“替换”，可更换为电脑中的 PNG、JPG、WebP、GIF、SVG 等图片。
- 点击“插入图片”，新图片会以合适尺寸出现在当前屏幕中央。
- 点击“插入文字”，会在当前屏幕中央创建一个黑色的正方形文字框。
- 新增的图片和文字都可以继续移动、缩放和编辑。

### 4. 元素复制与删除

- 点击“复制元素”会立即创建一个相同的新元素。
- 新副本默认向右下偏移 `16px`，便于确认复制成功。
- 副本采用独立定位，不会挤动原有文字或其他页面元素。
- 点击“删除元素”可隐藏当前元素，并可通过撤销恢复。

### 5. 样式复用与单项回退

- “复制样式”和“粘贴样式”可快速统一同类元素的视觉样式。
- 粘贴样式不会覆盖元素的文案、图片和位置。
- 只有本次编辑中发生变化的属性才会显示 `↺` 按钮。
- 点击 `↺` 只恢复该项，不影响其他修改。

### 6. 撤销、恢复与历史版本

- 工具栏中的 `↶` 用于撤销修改，`↷` 用于恢复刚撤销的修改。
- 支持 `Ctrl + Z`、`Ctrl + Shift + Z` 和 `Ctrl + Y`。
- 点击“保存”会将当前结果保存到浏览器本地，每个页面最多保留最近 5 个版本。
- “更多 → 恢复历史”可恢复初始状态或之前保存的版本。
- 点击“取消”会放弃本次尚未保存的修改。

## 安装方法

仓库已经包含构建完成的 `dist/` 文件夹，普通用户不需要安装 Node.js，也不需要执行构建命令。

1. 在 GitHub 仓库页面点击 **Code → Download ZIP**。
2. 解压下载的 ZIP 文件。
3. 在 Chrome 地址栏输入 `chrome://extensions` 并打开。
4. 开启页面右上角的“开发者模式”。
5. 点击“加载已解压的扩展程序”。
6. 选择解压目录中的 **`dist` 文件夹**，不要选择项目最外层文件夹。
7. 在扩展卡片中点击“详情”，开启“允许访问文件网址”。
8. 建议把 **HTML Visual Tweaker** 固定到浏览器工具栏，方便随时显示或隐藏编辑器。

安装完成后，扩展卡片中显示的版本应为 `0.10.6`。

## 首次使用

1. 用 Chrome 打开需要修改的本地 HTML，例如：

   ```text
   file:///E:/example/index.html
   ```

2. 点击浏览器工具栏中的 **HTML Visual Tweaker** 图标。
3. 页面右上角出现“HTML 微调器”后，点击“修改”。
4. 点击页面中需要调整的元素。
5. 在属性面板修改内容和样式，或直接拖动、缩放元素。
6. 修改完成后，根据需要选择“保存”“导出副本”或“覆盖原文件”。

如果点击扩展图标后没有显示工具栏，请检查：

- 当前地址是否以 `file://` 开头。
- 扩展详情中的“允许访问文件网址”是否已开启。
- 扩展是否已重新加载，目标页面是否已刷新。

## 常用操作

### 修改文字和样式

1. 点击“修改”。
2. 选择文字或其他元素。
3. 在面板中编辑“文案”，或调整字体、字号、颜色、宽高等属性。
4. 点击“保存”保留这次修改记录。

### 替换图片

1. 选择 `<img>` 图片，或只包含一张图片的常见图片容器。
2. 在属性面板中点击“替换”。
3. 从电脑中选择新图片。
4. 如需撤回本次替换，点击图片属性旁的 `↺`。

### 插入内容

- 点击“插入图片”并选择图片文件，新图片会出现在当前屏幕中央。
- 点击“插入文字”，页面中央会出现一个可编辑的黑色文字框。
- 插入后可直接拖动、缩放或继续修改属性。

### 复制或删除元素

- 选择元素后点击“复制元素”，插件会立即创建副本并向右下偏移 `16px`。
- 选择元素后点击“删除元素”，该元素会从页面中隐藏。
- 复制和删除都可以通过撤销按钮恢复。

## 保存、导出和覆盖的区别

| 操作 | 是否写入文件 | 用途 |
| --- | --- | --- |
| 保存 | 否 | 将当前版本保存在 Chrome 本地存储中，方便继续编辑和恢复历史 |
| 导出副本 | 是，生成新文件夹 | 保留原文件不变，生成一份可以独立打开的新版本 |
| 覆盖原文件 | 是，修改原 HTML | 将最终修改写回当前 HTML，并保存新增或替换的图片资源 |

### 保存

“保存”只写入浏览器本地存储，不会创建文件，也不会修改原 HTML。关闭扩展后，这些修改不会成为原文件的一部分；重新启用扩展并打开同一地址时，保存的版本仍可继续使用。

### 导出副本

点击“导出副本”后，扩展会在浏览器默认下载目录中生成：

```text
HTML Tweaker Exports/
└─ 当前项目文件夹名/
   ├─ 与源文件同名的 HTML
   ├─ html-tweaker-assets/
   └─ 页面引用的其他本地资源
```

- 原 HTML 不会被修改。
- 页面引用的本地图片、CSS、脚本和字体会尽量按原相对目录复制。
- 新增或替换的图片会保存到 `html-tweaker-assets/`。
- HTML 中使用相对路径引用图片，不会把大段 Base64 数据塞入文件。
- 输出 HTML 即使没有安装扩展，也能显示已经保存到文件中的修改。

### 覆盖原文件

点击“覆盖原文件”后：

1. 浏览器会要求选择一个文件夹。
2. 请选择当前 HTML 所在的文件夹。
3. 扩展会检查文件夹中是否存在同名 HTML，并确认它与当前页面一致。
4. 校验通过后，扩展覆盖该 HTML，并将新增或替换的图片写入 `html-tweaker-assets/`。

覆盖前会检查 HTML 是否完整，并保留原内容用于写入失败时恢复。浏览器基于安全限制必须让用户主动确认文件夹，扩展不能在未授权的情况下直接修改任意本地文件。

## 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `方向键` | 移动选中元素 `1px` |
| `Shift + 方向键` | 移动选中元素 `10px` |
| `Alt + 方向键` | 调整选中元素的宽度或高度 |
| `Ctrl + Z` | 撤销 |
| `Ctrl + Shift + Z` / `Ctrl + Y` | 恢复 |
| `Ctrl + Shift + C` | 复制样式 |
| `Ctrl + Shift + V` | 粘贴样式 |

## 更新扩展

1. 下载并解压最新版本，或更新本地项目文件。
2. 确认最新的 `dist/manifest.json` 中版本号正确。
3. 打开 `chrome://extensions`。
4. 点击扩展卡片上的“重新加载”。
5. 刷新已经打开的本地 HTML 页面。

只替换 README 不会更新插件功能；发布新版本时必须同时上传最新的 `dist/`。

## 数据与隐私

- 编辑历史保存在 Chrome 的 `chrome.storage.local` 中，并按本地页面地址区分。
- 扩展不会把页面内容或图片上传到网络。
- 只有主动点击“导出副本”或“覆盖原文件”时才会写入磁盘。
- “覆盖原文件”只会写入用户明确授权的文件夹。

## 当前限制

- 仅支持 Chrome 中通过 `file://` 打开的本地 HTML 页面。
- 暂不能单独选择没有独立 DOM 节点的 `::before` 和 `::after` 伪元素。
- 不编辑 Canvas 绘图内容、SVG 内部对象、跨域 iframe 或 Shadow DOM 内部节点。
- 扩展会递归查找 HTML、CSS 和模块脚本中明确引用的本地资源；脚本运行时动态拼接的资源地址可能无法自动识别。
- 在线 CDN 资源会继续使用原网络地址，不会下载到导出文件夹。

## 开发与构建

只有修改源码时才需要 Node.js 18 或更高版本：

```bash
npm install
npm run typecheck
npm run build
```

项目结构：

```text
src/                 扩展源码
public/manifest.json Manifest V3 配置
dist/                构建完成、可直接加载的扩展
```

每次修改源码后都应重新运行构建，并将新的 `dist/` 与源码一起上传到 GitHub。
